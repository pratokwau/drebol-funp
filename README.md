# drebol-funp

Веб-панель для работы с FunPay. Ставится на чистый Ubuntu одной командой:
скрипт сам спросит домен и порт, поставит nginx, выпустит SSL-сертификат,
создаст systemd-сервис и сгенерирует пароль администратора.

## Установка

```bash
curl -sSL https://raw.githubusercontent.com/pratokwau/drebol-funp/main/install.sh -o install.sh && bash install.sh
```

Если ты не под root — `sudo bash install.sh`.

> Не запускай через `sudo bash <(curl ...)` — `sudo` закрывает файловые
> дескрипторы, и получишь `bash: /dev/fd/63: No such file or directory`.
> И не через `curl ... | bash` — скрипт задаёт вопросы, а stdin будет занят.

Скрипт спросит:

| Вопрос | Пример | Что делает |
|---|---|---|
| Домен сайта | `funp.example.com` | на него выпускается SSL и настраивается nginx |
| Порт сайта | `443` или `8443` | **порт, на котором открывается сайт**: `443` → `https://домен`, любой другой → `https://домен:8443` |
| SSL Let's Encrypt | `Y` | certbot + автопродление |

Порт приложения внутри сервера подбирается сам (первый свободный из 8080-8130),
наружу он не торчит — снаружи доступен только выбранный тобой порт и 80-й
(на нём висит проверка домена для Let's Encrypt и редирект на твой адрес).

> Перед запуском поверни A-запись домена на IP сервера, а в файрволе хостера
> открой порт 80 и выбранный порт сайта — без 80-го Let's Encrypt не подтвердит
> домен и сайт останется на HTTP.

## Вход

После установки скрипт напечатает данные:

```
  Адрес:  https://твой-домен:8443
  Логин:  admin
  Пароль: <сгенерированный>
```

Тот же пароль печатается в консоль при каждом старте сайта:

```bash
journalctl -u drebol-funp -n 50 --no-pager
```

## Прибыль

Вкладка «Прибыль» — отчёт по чистой прибыли с кучей срезов.

**База заказов.** Чтобы отчёт открывался мгновенно, заказы хранятся на сервере
в `data/orders_cache.json`. Первый раз жми **«Загрузить всю историю»** — панель
скачает все продажи (по странице раз в ~1.2 с, чтобы FunPay не заблокировал;
при 429 ждёт и повторяет). Дальше **«Обновить заказы»** докачивает только
новое и перепроверяет заказы за последние 3 дня — у них ещё может смениться
статус. При открытии вкладки база обновляется сама, если ей больше 10 минут.

**Фильтры** (одна строка над всем отчётом, запоминаются в браузере):

- период: сегодня, вчера, 7 / 30 / 90 дней, этот и прошлый месяц, год, всё время,
  свой диапазон дат;
- с кэшбеком / без кэшбека;
- статусы заказов: закрытые, оплаченные, возвраты (по умолчанию первые два);
- раздел FunPay;
- шаг графика: авто, дни, недели, месяцы (авто: до 45 дней — дни, до 200 — недели);
- «только с закупом».

**Что показывает:**

- главное число — чистая прибыль, изменение к предыдущему такому же периоду и
  раскладка «выручка − комиссия − закуп = прибыль»;
- показатели: выручка, комиссия, закуп, маржа, ROI, средний чек, прибыль с
  заказа, сколько дал кэшбек, возвраты, число убыточных продаж;
- график по интервалам с переключателем «прибыль / выручка / заказы»:
  отрицательные значения уходят вниз другим цветом, подсказка при наведении,
  кнопка «Показать таблицей»;
- таблицы товаров, разделов и покупателей с полосками;
- теплокарта «Когда покупают» — заказы по дню недели и часу;
- худшие убыточные продажи со ссылками на заказы;
- продажи без закупа, которые не попали в прибыль.

Прибыль считается только по заказам, для которых найден закуп в «Мин. ценах» —
остальные входят в выручку, но не в прибыль, и панель прямо пишет, сколько их.

## Мин. цены

Вкладка «Мин. цены» хранит закупочные цены товаров — по ним панель сама считает
чистую прибыль каждой продажи.

1. **«Добавить игры с FunPay»** — сканирует профиль и показывает все разделы,
   где у тебя есть лоты (с количеством). Отмечаешь нужные, уже добавленные
   помечены и недоступны для повторного выбора. Есть «Выбрать все» (берёт всё,
   что видно с учётом поиска) и «Снять выбор».
2. **Открываешь игру** — внутри заводишь товары: вручную (название, ключевые
   слова, закуп, цена с кэшбеком) или кнопкой **«Подтянуть лоты с FunPay»** —
   тогда список лотов раздела появляется прямо здесь, остаётся вписать цены
   напротив нужного. Уже заведённые лоты помечаются.
3. **Комиссия FunPay** и **порог кэшбека** задаются сверху (3% и 100 ₽ по
   умолчанию) и сохраняются.

### Кэшбек

У товара две цены закупа: обычная и **с кэшбеком** — сколько реально списывает
банк. Например, товар стоит 764.75 ₽, а с кэшбеком выходит 757.75 ₽.
Вторая цена необязательна: пусто — значит кэшбека по товару нет.

Кэшбек работает только от суммы покупки, заданной в «Кэшбек от, ₽»
(по умолчанию 100). Если закуп ниже порога — считается обычная цена, даже когда
цена с кэшбеком указана. Такие товары в списке помечены жёлтым с ⚠.

Во вкладке «Заказы» сверху переключатель **«С кэшбеком / Без кэшбека»** — обе
прибыли считаются на сервере сразу, поэтому переключение мгновенное, без
перезагрузки. Заказы, где кэшбек реально применился, помечены зелёной точкой.
Выбранный режим запоминается в браузере.

В списке своих игр тоже есть массовый выбор: галочка у каждой игры, «Выбрать
все» сверху и кнопка «Убрать выбранные (N)» — удаляет отмеченные игры вместе с
их товарами за один раз, по подтверждению.

Сопоставление с продажами идёт по названию, разбитому на слова и числа: товар
подходит заказу, если его слова идут подряд внутри названия заказа. Пробелы,
регистр и знаки не мешают — «Гемы 170 шт» найдётся в «Brawl Stars | Гемы 170шт».
**Числа сравниваются целиком**: «50 голосов» не подойдёт к заказу на
«500 голосов» или «1500 голосов». Если названия совсем разные, помогают
ключевые слова: товар подойдёт, когда все слова есть в названии заказа.
Из нескольких подходящих выигрывает самое точное совпадение.

В строке заказа под названием видно, по какому товару взят закуп. Если у товара
закуп не задан (0), прибыль подсвечивается жёлтым с ⚠ — в «Мин. ценах» такой
товар помечен как «не задан».

Формула та же, что в калькуляторе, с учётом количества в заказе:

```
прибыль = цена_заказа × (1 − комиссия/100) − закуп × количество
```

Во вкладке «Заказы» появляется колонка прибыли (зелёная/красная), сверху —
суммарная прибыль по загруженным заказам и счётчик вида «3 из 4». Заказы без
заведённого закупа показывают «—» и попадают в подсказку внизу.

Данные лежат в `data/pricing.json` (права 600).

## Заказы

Вкладка «Заказы» показывает продажи с FunPay — страницами по 100, как их отдаёт
сам FunPay. Долистал вниз, нажал «Загрузить ещё 100» — подгружается следующая
сотня, и так до конца.

В строке: номер заказа, название товара с категорией и количеством, покупатель,
статус (закрыт / оплачен / возврат), сумма и дата со временем. Клик по строке
открывает заказ на funpay.com. Сверху — счётчик загруженных и их общая сумма,
рядом поле фильтра по уже загруженным заказам (товар, покупатель, номер).

## Калькулятор

Вкладка «Калькулятор» считает чистую прибыль с учётом комиссии FunPay —
комиссия снимается с цены продажи:

```
прибыль = цена_продажи × (1 − комиссия/100) − цена_закупа
```

Два режима:

- **Прибыль от цены** — ввёл закуп, цену продажи и комиссию, получил прибыль.
- **Цена от прибыли** — ввёл закуп и желаемую прибыль, получил цену, за которую
  выставлять лот.

Дополнительно показывает комиссию в деньгах, сколько придёт на баланс, наценку
к закупу и безубыточную цену. Есть количество (прибыль × шт) и кнопка
«Скопировать расчёт» — кладёт результат в буфер в том же виде, что на экране.
Считает на лету, комиссия и количество запоминаются в браузере.

## Настройки

Раздел «Настройки» в панели:

- **Golden key** — из cookie `golden_key` на funpay.com. Сохраняется в
  `data/settings.json` (права 600), в интерфейсе показывается замаскированным.
  Кнопка «Сохранить и получить данные» заходит с ключом на FunPay через
  библиотеку FunPayAPI и показывает карточку аккаунта: **ник, ID, баланс,
  активные продажи и покупки**. Эти данные запоминаются и видны на главной.
- **User-Agent** — должен совпадать с браузером, из которого взят ключ, иначе
  FunPay выкинет сессию. Кнопка «Стандартный UA» подставляет дефолтный.
- **Обновление с GitHub** — показывает текущий коммит, проверяет новые
  (`git fetch`), а по кнопке забирает их, ставит зависимости и перезапускает
  сервис. Лог обновления виден прямо на странице.

Обновление делает `git reset --hard` до состояния репозитория: локальные правки
в папке панели уезжают в `git stash`, а `.env`, `data/` и `venv/` не трогаются.

## Что ставится

- `/root/drebol-funp` — код и виртуальное окружение (права 700, сервис работает от root)
- `/root/drebol-funp/.env` — логин, пароль, адрес сайта, секретный ключ (права 600)
- `drebol-funp.service` — systemd-сервис: `systemctl enable` при установке, автостарт после ребута, рестарт через 3 сек при падении
- nginx-конфиг `/etc/nginx/sites-available/drebol-funp` — слушает твой порт, проксирует на приложение
- certbot с автопродлением сертификата
- `/root/drebol-funp/data/` — настройки FunPay, мин. цены, база заказов и лог обновлений (в git не попадает)

## Управление

```bash
systemctl status drebol-funp      # состояние
systemctl restart drebol-funp     # перезапуск
systemctl is-enabled drebol-funp  # автозагрузка (должно быть enabled)
journalctl -u drebol-funp -f      # живой лог
```

Автозагрузка включается установщиком сама: сервер перезагрузился — сайт поднялся
без тебя; процесс упал — systemd перезапустит его через 3 секунды, сколько бы раз
это ни повторилось. Выключить автостарт: `systemctl disable drebol-funp`.

Сменить пароль: отредактировать `ADMIN_PASSWORD` в `/root/drebol-funp/.env`
и перезапустить сервис.

Сменить порт сайта: просто запустить установщик заново и ввести новый порт —
пароль и сертификат сохранятся.

Повторный запуск установщика обновляет код из git и сохраняет существующий `.env`
(логин и пароль не меняются). Если панель стояла в `/opt/drebol-funp`, установщик
сам перенесёт её в `/root/drebol-funp` вместе с паролем.

## Стек

Python 3.10+ + FastAPI + uvicorn, nginx, certbot, systemd. Фронтенд — статика без сборки.
Работа с FunPay — через библиотеку [FunPayAPI](FunPayAPI) (лежит в репозитории,
зависимости: requests, requests-toolbelt, beautifulsoup4, lxml).

**Требуется Ubuntu 22.04 или новее** — FunPayAPI не работает на Python ниже 3.10,
установщик проверяет это и предупредит.
